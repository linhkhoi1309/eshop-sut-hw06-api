# Stage S4: Security Test Cases for API 1 (`PUT /api/users/me`)

## Test Cases

| ID | Title | Technique | Preconditions | Request | Expected Status | Expected Body | Spec Justification |
|---|---|---|---|---|---|---|---|
| A1-S4-01 | SEC-06: Attempt to change role via mass assignment | Privilege Escalation (Mass Assignment) | Logged in as User | `PUT /api/users/me` <br>Headers: `Authorization: Bearer <valid_user_jwt>`<br>Body: `{"role": "admin"}` | 400 or 200 (Role unchanged) | Role must not be updated to 'admin'. If 200, subsequent GET must show role='user' | FR-04: "không thể tự thay đổi thuộc tính role", SEC-06: "API cập nhật hồ sơ không được cho phép thay đổi trường role từ client." |
| A1-S4-02 | SEC-06: Attempt to change email via mass assignment | Mass Assignment | Logged in as User | `PUT /api/users/me` <br>Headers: `Authorization: Bearer <valid_user_jwt>`<br>Body: `{"email": "hacked@evil.com"}` | 200 or 400 | Email must remain unchanged. | FR-04: "Email không được phép thay đổi qua giao diện." |
| A1-S4-03 | SEC-06: Attempt to change ID via mass assignment | Mass Assignment | Logged in as User | `PUT /api/users/me` <br>Headers: `Authorization: Bearer <valid_user_jwt>`<br>Body: `{"id": 999}` | 200 or 400 | ID must remain unchanged. | FR-04 only allows updating: Họ Tên, Số điện thoại, Địa chỉ giao hàng mặc định. |
| A1-S4-04 | SEC-06: Attempt to change password via mass assignment | Mass Assignment | Logged in as User | `PUT /api/users/me` <br>Headers: `Authorization: Bearer <valid_user_jwt>`<br>Body: `{"password": "hacked"}` | 200 or 400 | Password must remain unchanged. | FR-04 specifies allowed fields for update. Password must use separate change flow. |
| A1-S4-05 | SEC-06: Attempt to change login_attempts via mass assignment | Mass Assignment | Logged in as User | `PUT /api/users/me` <br>Headers: `Authorization: Bearer <valid_user_jwt>`<br>Body: `{"login_attempts": 0}` | 200 or 400 | login_attempts must remain unchanged. | FR-04 specifies allowed fields for update. |
| A1-S4-06 | SEC-02: Missing Authorization header | Missing Authentication | None | `PUT /api/users/me` <br>Headers: (No Authorization header)<br>Body: `{"name": "New Name"}` | 401 | `{"error": "Unauthorized"}` (or similar) | SEC-02: "Các API có tính bảo mật phải yêu cầu JWT Token hợp lệ." |
| A1-S4-07 | SEC-02: Malformed JWT token | Invalid Token | None | `PUT /api/users/me` <br>Headers: `Authorization: Bearer invalid_token`<br>Body: `{"name": "New Name"}` | 403 | `{"error": "Forbidden"}` (or similar) | SEC-02: "Các API có tính bảo mật phải yêu cầu JWT Token hợp lệ." |
| A1-S4-08 | SEC-02: Empty Bearer token | Missing Token | None | `PUT /api/users/me` <br>Headers: `Authorization: Bearer `<br>Body: `{"name": "New Name"}` | 401 | `{"error": "Unauthorized"}` | SEC-02: "Các API có tính bảo mật phải yêu cầu JWT Token hợp lệ." |
| A1-S4-09 | SEC-04: XSS payload in name field | Cross-Site Scripting (XSS) | Logged in as User | `PUT /api/users/me` <br>Headers: `Authorization: Bearer <valid_user_jwt>`<br>Body: `{"name": "<script>alert(1)</script>"}` | 200 | Profile updated successfully. Output must be safely encoded or stored as-is without execution context. | SEC-04: "Mọi dữ liệu từ user nhập vào khi hiển thị trên UI phải được escape đúng cách" |
| A1-S4-10 | SEC-05: SQL Injection payload in phone field | SQL Injection | Logged in as User | `PUT /api/users/me` <br>Headers: `Authorization: Bearer <valid_user_jwt>`<br>Body: `{"phone": "'; DROP TABLE users; --"}` | 200 | Profile updated successfully. Phone field contains literal payload, no DB errors. | SEC-05: "Truy vấn CSDL phải dùng Parameterized Query, không nối chuỗi trực tiếp." |
| A1-S4-11 | SEC-01: Password exposure check via GET | Data Exposure | Logged in as User | `GET /api/users/me` <br>Headers: `Authorization: Bearer <valid_user_jwt>` | 200 | Response MUST NOT contain plaintext `password` field. | SEC-01: "Mật khẩu không được lưu dưới dạng plaintext." and general PII protection. |

*Note: SUT behaves improperly for A1-S4-01 by successfully updating the role, as evident in its source code. Also, the returned information for GET /api/users/me contains plaintext passwords, exposing a vulnerability related to SEC-01.*
